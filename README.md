# DUO ARENA — 2人対戦スマホPWA

アカウント不要で、2台のスマートフォンから同じルームに参加して対戦するWebアプリです。iOS Safari / Android Chromeを想定したモバイルファーストUIを備えます。**Hit & Blow と J-POP曲名早押しクイズの2本が実装済み。残り2本は依頼どおり「COMING SOON」のダミー枠です。**

## 1. 収録内容

| 項目 | 状態 |
|---|---|
| ルーム作成、6桁コード、招待URL、2名参加、準備完了 | 実装済み |
| 同じWi-Fi不要のリアルタイム通信 | WebSocket（公開サーバーが必要） |
| iPhone / Android対応PWA、ホーム画面追加 | 対応（実機未検証） |
| Hit & Blow（3桁、重複禁止、先頭0、履歴、時間、ヒント、引き分け） | 実装済み |
| 歌詞型早押し（段階表示、サーバー判定、4択・キーボード、ルール、得点） | 実装済み。出題文章は**実際の歌詞ではないオリジナルデモ** |
| ゲーム③・④ | プレースホルダー（対戦・開始は不可） |
| 再戦、ゲーム変更、履歴、通信断・再接続 | 実装済み（履歴はサーバーメモリ上のみ） |
| 公開済みのインターネットURL | 未実施（Render等へのデプロイ操作が必要） |

### 著作権・曲データについて

`data/songs.json` の20曲には、曲名・アーティスト名と、本作で独自に作成した**架空の説明文**を収録しています。**実際の歌詞ではありません。** アプリ内にも明記しています。歌詞の利用権原を確認せずに、Web上の歌詞をコピーして公開しないでください。

正式な歌詞データを扱う場合、権利者・出版社等から必要な許諾を得た文章、または利用権限を確認できるユーザー提供の文章を `text` に設定し、利用可能な範囲を記録してください。配信・複製・公衆送信・二次利用などの許諾範囲に注意が必要です。

## 2. 技術選定

- **フロント：依存パッケージ不要のES Modules JavaScript + CSS**。画面はスマホ優先、PWA Manifest + Service Worker。
- **サーバー：Node.js 20+ の標準 HTTP + WebSocket**。外部ライブラリ不要のため、`npm install` 不要。通信は単一Nodeプロセスで管理。
- **ゲーム状態：サーバーメモリ**。2名のログイン不要の短い対戦向け。秘密数字・正誤・得点・回答権はサーバーだけが保持・判定。
- **データベース：現時点で不要**。永続履歴や複数サーバーに拡張する場合、Postgres/Redisの導入を推奨。

React / TypeScriptの導入ではなく依存ゼロ構成にした理由は、個人運用の簡便さと、依存パッケージをダウンロードできない開発環境でも完成品を起動・自動検証できることを優先したためです。将来Reactへ置き換える場合、WebSocketのメッセージ契約とサーバーをそのまま流用できます。

**注意：** `server/websocket.mjs` はこの用途向けの小型RFC6455実装です。多数のユーザーを扱う公開サービスへ拡張する際は、`ws` / `Socket.IO` など十分に運用実績のあるWebSocketライブラリへ置換してください。負荷制限、永続化、監視も追加が必要です。

## 3. ローカルで起動

Node.js 20以上をインストールして、解凍した `duo-arena` フォルダで実行します。

```bash
node --version
npm start
```

`http://localhost:3000` を開きます。別のターミナルから `PORT=4000 npm start` でポートも変更できます。**依存ライブラリのインストールも、環境変数・APIキー・DBの設定も不要です。**

開発時は次のコマンドも利用できます。

```bash
npm run dev      # Node.js --watch でサーバーを再起動
npm run check    # ソースの構文検査
npm test         # ロジック・実際のWebSocket対戦を自動テスト
```

### スマホから利用する

**ローカルでは** PCとスマートフォンを同じLANに接続し、PCのIPアドレスを調べて `http://192.168.x.x:3000` などにアクセスします（PCのファイアウォールも確認）。ただし、HTTPSでないLAN内アクセスではService Worker / PWAの一部機能が動作しない場合があります。

**別の場所からオンライン対戦する場合**、下記の手順でHTTPS対応の公開Webサーバーにデプロイします。ローカル `localhost` のアドレスをそのまま友達に渡してもアクセスできません。

## 4. インターネットへの公開（Renderの例）

`render.yaml` はリポジトリ直下にあります。

1. ソース一式を自分のGitHubリポジトリへアップロードし、公開/非公開どちらでも構いません（Renderとの連携許可が必要）。
2. [Render](https://dashboard.render.com/) にログインして `New > Web Service` を選び、該当リポジトリを選択します。
3. Runtimeは `Node`、Build Commandは `npm run check`、Start Commandは `npm start`、Health Checkは `/health` とします。
4. コストを抑える場合は利用可能な `Free` インスタンスを選択します。Render側で `PORT` が自動的に設定されます。
5. デプロイ完了後に発行される `https://<サービス名>.onrender.com` を両方の端末で開きます。
6. 片方がルームを作成し、表示された招待URLをもう片方に送ります。

現時点のRender無料Webサービスには**非通信時15分でスリープ、初回アクセス時の復帰待ち、再起動でメモリ上のルーム・対戦履歴が消える**といった制限があります。WebSocketの送受信が継続する対戦中は原則通信として扱われますが、サービスの再起動可能性は残ります。これらは無料運用上の制約であり、ゲームの永続性を保証しません。安定した継続運用には有料インスタンス＋永続DB等を推奨します。

参考：https://render.com/docs/free

### PWAのホーム画面追加

- iPhone：SafariでHTTPSの公開URLを開き、「共有」→「ホーム画面に追加」。
- Android：ChromeでHTTPSの公開URLを開き、ブラウザメニューの「ホーム画面に追加」または「アプリをインストール」。

アプリの外観と配布用ファイルはPWA対応していますが、**サーバーが必要な対戦はオフラインではできません**。

## 5. 遊び方

### 共通

1. Aがルームを作成してコード/招待リンクを送る。
2. Bがリンクまたはコードで参加。
3. Aがゲームとルールを決める。A・Bがそれぞれ準備ボタンを押すと自動開始。
4. 終了後、互いに再戦を選択すればすぐ開始。Aはゲーム選択画面にも戻れる。

### Hit & Blow

- 各プレイヤーが秘密の異なる3桁を設定（先頭0は標準で許可）。
- お互い相手の数字を交互に推測。3 Hitで正解。
- 各ラウンド、先攻と後攻の**各1回答**を終えてから判定。両方正解なら引き分け。
- 先攻・後攻は再戦時に交代。時間切れはその手番を失う。
- 正解した推測の数列は、**対戦が完全終了するまで対戦相手には伏せ字で表示**。秘密そのものはサーバーのみに保存。
- ヒントON時は「相手の秘密に含まれる偶数の個数」を各人1回だけ確認可能。

### 歌詞型早押しクイズ

- 公開前の全文・答えはサーバーに保持し、各クライアントには**公開済み文字だけ**を随時送信。
- 早押し受付はサーバー主導。最初の押下から160ms待って競合を回収し、直近の計測RTTによる最大75msの片道遅延補正を加えて判定。5ms以内のほぼ同着はランダム決定。
- 回答権を取ると、4択で1文字ずつ曲名を完成させる。途中で違う文字を押すと誤答。キーボード方式も選択可。
- 先取点数、加点、減点、誤答後の扱い、再回答、表示速度、難易度、年代、回答秒数をルーム主催者が設定。
- 問題が全て表示された後も12秒の早押し猶予があり、反応がなければ次の問題に移ります。

**公平性に関する限界：** 通信遅延は完全には測れず、端末性能やネットワークの混雑にも左右されます。サーバーの到着順・RTTで補正しますが、同じ条件のオフライン同時対戦と完全同等の公平性は保証できません。改ざん可能なクライアント送信時刻は勝敗判定には使いません。

## 6. 曲を追加・編集する

サーバー側の `data/songs.json` の1件を編集・追加します。**このJSONは`public/`の外にあるため、HTTPの静的配信では直接アクセスできません。**

```json
{
  "id": "unique-track-id",
  "title": "楽曲のタイトル",
  "artist": "アーティスト",
  "era": "令和",
  "difficulty": "easy",
  "source": "licensed-or-user-provided",
  "text": "利用許諾を確認した本文、または自作のデモ文章"
}
```

`era` は `昭和` / `平成` / `令和`、`difficulty` は `easy` / `medium` / `hard`。`source` はライセンス情報を自分で記録するための自由欄で、**この文字列を記載しただけで著作権上の利用権限が得られるわけではありません**。追加後、サーバーを再起動します。出題候補の重複は1試合内で回避します。

さらに回答表記の揺れを増やす場合は `server/engine.mjs` の `normalizeAnswer()`、`server/index.mjs` のキーボード回答照合に別名 (`aliases`) を追加してください。

## 7. 今後ゲームを追加する

現在、ゲーム3・4はメニュー上に表示するだけのダミーです。**「遊べる」「開始できる」と誤認されないよう無効化しています。**

新しいゲームを作る場合の主な編集箇所：

1. `public/app.js`: `gameCard` から呼び出すメニューを有効化し、新ゲームのUI描画関数と入力イベントを追加する。
2. `server/index.mjs`: `startGame` にゲーム状態初期化、`handle` に入力のサーバー検証、`tick` にタイマー管理、`stateFor` に各プレイヤー向けの公開情報を追加する。
3. `server/engine.mjs`: 純粋関数として独立させたルール・勝敗判定を追加する（できるだけここに置く）。
4. `tests/`: 2接続のWebSocket統合テストを追加する。

**アーキテクチャ上の改善余地：** 現状は小規模のためサーバーのイベント処理を単一ファイルにまとめています。5種類以上に増やす場合、各ゲームの `init / handleAction / tick / projectState` を `server/games/<id>.mjs` に分離して登録する構成へ移行すると保守性が上がります。

## 8. 通信とセキュリティの概要

- 接続IDとは別に、ブラウザのlocalStorageにランダム40文字の秘密セッショントークンを保持。リロードで同じプレイヤーに復帰。
- 他人の席に入れないようトークンで照合。ルームは最大2名。ホスト以外の設定変更を拒否。
- 数字・採点・回答権はサーバー側で検証。二重回答・時間切れ後の操作を拒否。
- WebSocket接続は同一Originを要求（ローカルの非ブラウザテストではOrigin省略を許容）。
- 接続断で双方のゲームタイマーを一時停止し、相手が復帰すると残時間を補正して再開。
- 1ルームの無操作状態が4時間続くと消去。データベースなしのためプロセス再起動でも消去。
- ルームコードはアクセス制御ではなく招待用コードです。会話や個人情報など機密データを送信しないでください。
- 本格公開時には接続数・ルーム生成数のレート制限、監査ログ、スパム対策、永続化、TLS、WebSocketライブラリ刷新等を推奨します。

## 9. 自動・手動テスト

`npm test` は以下を検査します。

- Hit & BlowのHit/Blow計算、数列の入力バリデーション、同ラウンド引き分け、先攻交代
- 4択候補が4つで正解が1つ、難易度・年代フィルタ、回答表記の正規化
- **実際のWebSocket接続2台分**を使ったルーム作成・参加、秘密の伏せ、再戦
- クイズ本文の時間的な段階公開、早押し競合、回答権判定、4択での正答と得点確定

実機でさらに確認してください：

1. iPhone SafariとAndroid Chromeから、公開URLへ接続。
2. 携帯データ回線と別Wi-Fiで同じルームへ参加。
3. 両者でHit & Blow、クイズの正解・誤答を通しでプレイ。
4. 片方のスマホ画面をロック／ブラウザをバックグラウンドへ／機内モード切り替え後に復帰。
5. 2人が0.1秒以内に同時早押しし、必ず1人だけ回答できるか確認。
6. Safari共有メニュー・Androidブラウザメニューからホーム画面へ追加。

**実機テストと公開デプロイは、この配布パッケージの作成環境では未実施です。** 端末やホスティング環境固有の不具合はデプロイ後に検証してください。

## 10. ファイル構造

```text
duo-arena/
├── data/songs.json           # 楽曲メタデータと著作権フリーのデモ用オリジナル文章
├── public/
│   ├── index.html            # HTMLエントリ
│   ├── styles.css            # モバイルファーストUI
│   ├── app.js                # WebSocketクライアントと画面・操作
│   ├── sw.js                 # PWAオフラインシェル用Service Worker
│   ├── manifest.webmanifest  # アプリ定義
│   └── icons/                # 192 / 512 アイコン
├── server/
│   ├── index.mjs             # 権威サーバー、ルーム、試合、静的配信
│   ├── engine.mjs            # pureなゲーム判定・候補生成
│   └── websocket.mjs         # WebSocket通信フレーム
├── tests/
│   ├── engine.test.mjs       # ロジック単体テスト
│   └── integration.test.mjs  # 2プレイヤーWebSocket結合テスト
├── render.yaml              # Render Blueprintsでの公開設定
└── package.json
```
